\subsection{Shared configuration checks}
The canonical JSON case separates physical inputs, initial conditions, study criteria, solver settings, and parameter provenance. Internal values use SI units. Every parameter has a classification and explanatory note. The baseline field constants are preliminary idealized inputs, not measured geomagnetic data.

The configuration loader checks required keys, finite values, symmetric positive definite inertia, a unit initial quaternion, valid angular units and ranges, positive controller gain and dipole limit, positive durations, and a hold interval that fits before the deadline. It rejects misspelled keys and unsupported controller laws. The initial quaternion is not silently corrected.

The baseline stores the historical one second step supported by the original numerical refinement evidence. The merged architecture requires renewed verification. Requesting ready solver settings with an unset step raises an explicit error. Physical callback inputs are exported separately from numerical and study settings. The generated report parameter table is checked against the same baseline file.

The configuration suite has 50 passing cases. A further report consistency check compares the parameter table with the canonical inputs. Configuration checks do not establish integration accuracy, a production time step, or engineering recovery performance. Numerical convergence is assessed separately using exact special cases.
