\section{Reproducibility}
The shared code is available in the \href{https://github.com/Yuvraj-Agarwal-101/CubeSat-Detumbling-with-Magnetorquers}{project repository}. The README records environment setup, module ownership, current commands, and outstanding reproduction requirements.

The available configuration and correctness checks can be reproduced from the repository root using
\begin{quote}
\texttt{.venv/bin/python \string-m src.config}\\
\texttt{.venv/bin/python \string-m tools.check\_project}.
\end{quote}
The second command runs the current test suite and records the Git revision, working tree status, Python version, test counts, and derived baseline timings in \texttt{report/build/verification.json}. These generated records describe available checks rather than a full engineering simulation.

The parameter table is generated with
\begin{quote}
\texttt{.venv/bin/python \string-m tools.export\_report\_inputs}.
\end{quote}
A consistency test fails if the stored table differs from the baseline configuration.

The Person 4 pipeline now provides \texttt{run\_all.py}, seeded study
configurations, metric tests, persisted case records, saved histories,
monochrome figure drivers, and figure manifests. Run
\texttt{python run\_all.py \string--demo} for an explicitly synthetic
pipeline demonstration. Run
\texttt{python \string-m studies.metric\_refinement} for the analytic
metric check. The latter uses exact sampled functions and no IVP integrator.
The README documents all generating commands.

The preliminary refinement audit compares three integration steps, audits
output spacing separately, and optionally records frozen Jacobian spectra.
Its outputs provide evidence for the numerical methods owner and do not
automatically approve a production step. The real study runner requires
independent physics checks, smooth convergence evidence, output grid
refinement and a step accepted by the numerical methods owner. The production
study also requires the real 108 case pilot. Convergence driver implementation,
real runtime measurements, and a clean clone reproduction of all final
engineering results remain required before submission. Evaluator access and the final tested revision must be checked after the remaining modules and results are merged.
